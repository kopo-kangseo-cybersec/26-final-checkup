# 🔎 최종 결과물 점검 (`26-final-checkup`)

> **13주차 사전과제** — 13주차(마지막 수업)에 포트폴리오를 만들기 전에, **4주차부터 12주차까지 만든 결과물의 배포 링크가 모두 살아 있는지** 점검해 제출합니다.
> 제출하면 **봇이 자동으로** 링크 접속 여부와 각 주차 PR 제출 여부를 확인해 결과를 알려 줍니다.

---

## 📅 제출 기한

- **13주차 수업 시작 전까지**
- 봇이 `보완 필요`라고 알려 주면, 링크를 고친 뒤 **같은 PR에 다시 푸시**하면 됩니다. 자동으로 다시 점검합니다.

---

## 📝 제출 방법 (GitHub 웹 화면에서 5분이면 끝!)

Clone할 필요 없이 **GitHub 웹 화면에서** 모두 할 수 있습니다.

1. 이 저장소를 본인 계정으로 **Fork**합니다.
2. 내 Fork 저장소에서 [`submissions/_TEMPLATE.md`](./submissions/_TEMPLATE.md)를 열고 내용을 **전부 복사**합니다.
3. 내 Fork 저장소에서 **Add file → Create new file**을 누르고, 파일 이름을 아래처럼 정확히 입력합니다.
   ```
   submissions/<내-GitHub-아이디>.md
   ```
   > 예: GitHub 아이디가 `hong-gildong`이면 `submissions/hong-gildong.md`
   > ⚠️ 아이디 철자와 대소문자가 다르면 봇이 내 파일을 찾지 못합니다.
4. 복사한 템플릿을 붙여 넣고, **이름**과 **각 주차 배포 URL**을 채운 뒤 **Commit changes**를 누릅니다.
5. **Contribute → Open pull request**를 눌러 PR을 보냅니다.
   - **base**: `kopo-kangseo-cybersec/26-final-checkup` (`main`)
   - **compare**: `<내아이디>/26-final-checkup` (`main`)
6. 1~2분 뒤 PR에 달리는 **점검 결과 코멘트**를 확인합니다.

> ⚠️ `submissions/<내아이디>.md` **한 파일만** 추가하세요. 다른 파일(README 등)을 수정하면 `보완 필요`로 처리됩니다.

## 🤖 봇이 점검하는 것

| 점검 항목 | 통과 기준 |
|---|---|
| **배포 링크 접속** | 적어 낸 주소에 실제로 접속되는가 (응답 코드 200번대) |
| **GitHub Pages 주소 주인** | `https://<내아이디>.github.io/...` — **내 아이디**의 주소인가 |
| **PR 제출** | 각 주차 원본 저장소에 **내가 보낸 PR**이 있는가 (PR 주소는 적지 않아도 봇이 직접 찾습니다) |

> 💡 봇은 **페이지가 열리는지**까지만 확인합니다. 로그인·데이터 저장 같은 **기능이 제대로 동작하는지는 13주차 수업 시간에** 함께 확인합니다.
> 예를 들어 9주차 감정 일기는 Supabase 프로젝트가 일시정지되어도 첫 화면은 열립니다. 미리 직접 접속해서 동작을 확인해 두세요.

## 🛠️ 링크가 ❌로 나왔을 때

| 증상 | 확인할 것 |
|---|---|
| `404` (GitHub Pages) | 해당 저장소 **Settings → Pages**에서 배포 브랜치가 설정되어 있는지, 저장소 이름이 바뀌지 않았는지 |
| `404` (Netlify) | Netlify 사이트를 삭제했거나 사이트 이름을 바꿨는지 — [app.netlify.com](https://app.netlify.com)에서 현재 주소 확인 |
| `내 아이디의 주소가 아님` | 다른 사람의 주소를 적지 않았는지, 아이디 철자가 맞는지 |
| `PR 없음` | 해당 주차 원본 저장소(`kopo-kangseo-cybersec/26-wXX-...`)로 PR을 보냈는지 — 내 Fork 저장소 안에서만 PR을 만든 건 아닌지 |

배포를 아직 못 했거나 PR을 안 보낸 주차가 있다면, **지금 해당 주차 저장소에서 마무리**한 뒤 다시 푸시하세요.
